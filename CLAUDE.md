# Pen

Личное PWA-приложение Данила «для организации жизни» (себя и жены). Называется **Pen** (лого — ручка с фигурой человека, чёрный фон; `app/icon.png`, `public/icon-192.png|icon-512.png|apple-icon.png`; тема `#000000`). Next.js 14 (App Router) + Neon (Postgres) + JWT-авторизация, задеплоено на **Vercel** (тот же проект). Установочное на телефон, тёмная тема, мобайл-фёрст, русский язык интерфейса. ВАЖНО: `middleware.ts` matcher исключает статику/манифест/иконки (иначе PWA-иконки редиректит на /login).

## Навигация (каркас)
Три раздела маршрутизируются в группе `app/(main)/` с общим `app/(main)/layout.tsx`: колонка `h-[100dvh]` → скроллящийся контент сверху + **нижняя панель `components/BottomNav.tsx`** (Трекер/Финансы/Напоминания), всегда видна. URL: `/tracker`, `/finance`, `/app`. Внутри раздела — своя навигация ВВЕРХУ (у трекера под-вкладки «Сегодня/Статистика» + FAB «+»; у финансов FAB для операции). НЕ добавлять вторые нижние бары внутри разделов. (Старый `SectionSwitcher` удалён.)

1. **Трекер** привычек — `/tracker` (готов).
2. **Напоминания** (то-ду) — `/app` (ядро проекта, НЕ ломать; его раскладка `flex h-full`, каркас даёт высоту). Спец-виды в сайдбаре: Главная (`__home__`, Dashboard), **Календарь** (`__calendar__`, `calendarContent` — сетка месяца по `task.dueDate`, тап по дню → задачи дня + добавление «мероприятия» = задача с дедлайном через `addEvent`, Пн-первый, `monthCells`), По важности (`__priority__`), Архив (`__archive__`). События = задачи с `dueDate`, отдельной сущности нет.
3. **Финансы** — `/finance` (готов): счета (баланс правится вручную), операции доход/расход (меняют баланс), умный депозит, мультивалюта.

Корень `/` → редирект на `/tracker` (стартовый экран; легко поменять). Всё, кроме `/login /register /join`, защищено `middleware.ts` (кука `auth_token`, JWT через `jose`).

## Технологии и конвенции
- Данные: `@neondatabase/serverless`, `neon(process.env.DATABASE_URL)`. Строка в `.env.local` (и в env Vercel). Таблицы префиксуются по разделу: `todo_*`, `tracker_*` (для финансов — `finance_*`). Пользователи — `todo_users` (id uuid). Запросы всегда скоупить по `user_id`.
- Авторизация: `lib/auth.ts` (sign/verify JWT), `lib/getUser.ts` (`getUserFromRequest()` из куки). Шаринг между людьми — паттерн `todo_section_members` + share-код (см. `lib/db.ts`).
- Стили: Tailwind. Раздел «Трекер» использует собственный CSS с префиксом **`tk-`** (`app/tracker/tracker.css`), чтобы не конфликтовать с утилитами Tailwind (`.block`, `.flex` и т.п.). Свитчер и todo — на Tailwind.

## Раздел «Трекер» (карта файлов)
- `lib/tracker.ts` — слой данных (getHabits/create/update/delete, setCompletion). Типы `Habit`, `Schedule`.
- `lib/trackerStats.ts` — клиентский расчёт (серии, %, тепловая карта, недели). Ключевая метрика — **«серия без пропусков»** (`globalStreak`): дней подряд, когда выполнены ВСЕ привычки дня; дни без запланированных привычек нейтральны; сегодня с поблажкой.
- `app/tracker/page.tsx` — вся UI (экраны Сегодня / привычка / Статистика + шторка добавления), клиентский, тянет данные из API с оптимистичным обновлением.
- `app/api/tracker/habits/route.ts`, `.../[id]/route.ts`, `app/api/tracker/completions/route.ts` — API.
- **Несколько раз в день**: `tracker_habits.target_per_day` (int, 1 = обычная привычка) + `tracker_completions.count`. `Habit.counts` (день→число) и `Habit.completions` (дни, где count ≥ target — «день засчитан полностью»). Вся статистика (`trackerStats.ts`, серии/%/тепловая карта) работает на `completions`, т.е. на ПОЛНОСТЬЮ выполненных днях — менять её не нужно. API отметки: `PUT /api/tracker/completions {habitId, day, count}` (setCount, клампит 0..target); старый `{done}` (setCompletion) сохранён для совместимости. В UI тап по чекбоксу привычки инкрементит счётчик (0→1→…→target→0), на строке и в детали видно `N/target`. Миграция: `scripts/migrate-habit-perday.mjs`.
- Схема: `tracker_habits` (id, user_id, name, description, emoji, color, schedule jsonb, start_date, archived, sort_order, created_at, **target_per_day**), `tracker_completions` (habit_id, day, **count**, PK(habit_id,day)), каскадное удаление. Расписание: `{type:'daily'}` | `{type:'weekdays',days:[0..6]}` (Пн=0) | `{type:'count',perWeek:N}`.

## Деплой
`git push` → Vercel пересобирает тот же проект на том же домене. Neon — та же база (`DATABASE_URL`). Миграции применяются вручную скриптом через `@neondatabase/serverless` (пример — как создавались `tracker_*` таблицы).

## Раздел «Финансы» (карта файлов)
- **КАБИНЕТЫ (spaces)** — всё в финансах живёт внутри кабинета (`finance_spaces` + `finance_space_members`): личный / семейный / бизнес. Доступ по share-коду (паттерн как у todo-секций). Участник кабинета видит и правит ВСЁ в нём. Все запросы скоупятся по членству (join на `finance_space_members`), НЕ по `user_id` (он остался как автор/владелец). У каждого пользователя при первом GET /spaces автосоздаётся кабинет «Личный». Активный кабинет — в `localStorage.fin_space`.
- `lib/finance.ts` — данные: кабинеты (`getSpaces`/`createSpace`/`joinSpaceByCode`/`leaveSpace`/`deleteSpace` — удаляет только owner, каскад), счета (`finance_accounts`), ставки депозита (`finance_deposit_rates`), настройки/курсы кабинета (`finance_space_settings`), операции (`finance_txns`). Типы `Space`, `Account`, `DepositRate`, `Txn`, `FinanceSettings`, `AccountType`, `TxnType`. numeric → `::float8`. `createTxn`/`deleteTxn` меняют баланс счёта **атомарно** через `q.transaction([...])`.
- `lib/financeCalc.ts` — `depositValue` (учитывает капитализацию: `monthly` → помесячное сложение номинальной ставки, `none` → простое; между периодами баланс переносится), `effectiveRate` (номинал→эффективная годовая), `accountValue`, `convert`/`combinedTotal` (пересчёт в базовую валюту по ручным курсам), `formatMoney`, `EXPENSE_CATEGORIES`/`INCOME_CATEGORIES`/`categoryMeta`, `ACCOUNT_TYPES`.
- `app/(main)/finance/page.tsx` — UI: чипы кабинетов сверху (`SpaceBar`) + шторка `SpaceSheet` (переключение/создание/переименование/код доступа/подключение по коду/участники/выход/удаление), список (итог по валютам + общий ≈ в базовой; счета; последние операции), детали счёта (+ операции; для депозита — капитализация/эффективная ставка/менеджер ставок/**кнопки «Пополнить депозит» и «Начислить % за месяц»**), быстрая операция, формы счёта и курсов. FAB = добавить операцию. Стили: `../tracker/tracker.css` (`tk-`) + `finance.css` (`fin-`).
  Настройки — шестерёнка ⚙ → меню: Кабинеты и доступ / Курсы валют / Категории / Бюджеты (`SettingsMenu`, `SpaceSheet`, `RatesSheet`, `CategoriesSheet`, `BudgetsSheet`). Валюты ограничены `₸ € $` (`CURRENCIES` в page). Операция поддерживает 3 типа: расход/доход/**перевод**.
- Депозит: тело (`principal`) + проценты-«оценка» с `start_date` по ставкам. Кнопка «Начислить % за месяц» = `principal += principal × ставка/1200`, `start_date` сбрасывается на сегодня (чтобы оценка не задваивала начисленное). «Пополнить» = `principal += X`.
- API: `spaces` (GET/POST, +`[id]` PATCH/DELETE, +`[id]/leave` POST, +`join` POST по коду), `accounts` (+`[id]`), `rates` (+`[id]`), `txns` (+`[id]`), `settings` (GET/PUT), `categories` (+`[id]`), `budgets` (GET/PUT), `transfers` (POST). GET-ы списков требуют `?spaceId=`, POST-ы создают внутрь `spaceId` из тела. ВАЖНО: у route-хендлеров, где try/catch оборачивает `cookies()`, ставить `export const dynamic = 'force-dynamic'` — иначе Next запечёт роут статически (пустой ответ навсегда).
- Схема: `finance_spaces` (id, name, emoji, owner_id, share_code UNIQUE), `finance_space_members` (PK(space_id,user_id)), `finance_space_settings` (space_id PK, base_currency, rates jsonb), `finance_accounts` (…, space_id, capitalization monthly|none), `finance_deposit_rates`, `finance_txns` (space_id; type **expense|income|transfer**, category=**id категории**, +`to_account_id`,`to_amount` для переводов), `finance_categories` (space_id; kind expense|income; сидятся дефолтом при первом GET кабинета), `finance_budgets` (space_id; category_id UNIQUE, amount — месячный лимит в базовой валюте). Легаси-таблица `finance_settings` (per-user) больше не используется — заменена `finance_space_settings`.

Модель: учёт **по балансам** + операции доход/расход/перевод (двигают баланс атомарно через `q.transaction`). Категории **пользовательские** у каждого кабинета. Бюджеты — лимит на категорию/мес (`categorySpend`). Мультивалюта — ручные курсы к базовой (не онлайн). ШАРИНГ ГОТОВ: кабинеты с доступом по коду (жена подключается через Настройки → Кабинеты и доступ → «Подключиться по коду»).
